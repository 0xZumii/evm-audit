evm-audit

Read a contract before you trust it.

Paste Solidity and read the structural pass: who can call what, whether a state write happens after an external call, where tx.origin or delegatecall appears, and what a signature or price feed is missing.

It is a lexer, not a compiler. It does not resolve inheritance, check types, or follow control flow, and it never says a contract is safe.

Read a deployed contract's runtime code, or raw 0x bytecode. Files are CLI-only, so this page cannot ask the server to read local files.

Features and disassembly work on raw hex with no network. An address needs an RPC endpoint (the CLI's default public one).

See what a payload actually authorises. These run entirely locally — no network, no signature.

The inverse question: forget payloads — what can be taken from an address without another signature? It finds candidate approvals in logs and re-reads current state for each one.

Logs are the sieve; the state read is the truth. This is bounded by the block range and token list, and it can be slow. "None found" means none in what was scanned — not "safe".

evm-audit is a zero-dependency toolkit for contract auditing and web3 threat research. This page is a local front end for every layer; the same functions are reachable from the CLI.

The layers

  • Source — a Solidity lexer and structural pass: access control, call ordering, tx.origin, initializers, signature and oracle shapes.
  • Bytecode — disassembly, structural features, proxy detection (EIP-1167 / EIP-1967 / ZeppelinOS), and on-chain implementation resolution.
  • Decode — transaction calldata and 4-byte selector derivation, in plain language.
  • Sign — EIP-712 typed-data decoding, secp256k1 signer recovery, and a domain-separator check against the contract.
  • Approvals — standing ERC-20 / ERC-721 / Permit2 allowances, re-read from current state.

What it will not do

  • It never says safe or unsafe. Every finding is a place to look; absence of findings is not a clean bill of health.
  • The source layer is syntactic. Inheritance is not resolved, types are not checked, control flow is not evaluated.
  • Bytecode cannot see the dominant attack. Most drains are signature phishing — a legitimate contract, a malicious payload. That is what the Decode and Sign layers are for.
  • Approvals are bounded. An approval before the scanned range, or on a token not in the list, is invisible here.

The CLI

python -m evm_audit source contracts/MyToken.sol
python -m evm_audit features 0xA0b8...eB48
python -m evm_audit disasm 0xA0b8...eB48 --limit 60
python -m evm_audit resolve 0xA0b8...eB48 --features
python -m evm_audit calldata 0x095ea7b3...
python -m evm_audit typed-data permit.json --signature 0x... --check-domain
python -m evm_audit eip712 0xA0b8...eB48 --name "USD Coin" --version 2
python -m evm_audit allowances 0xOwner... --tokens tokenlist.json
python -m evm_audit serve

Runs on a local server bound to 127.0.0.1. Input is analyzed in memory and not written anywhere. A request leaves the machine only to read a chain: an RPC for code or state, and Sourcify for verified source.
